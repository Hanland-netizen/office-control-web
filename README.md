# Веб-панель управления «Офис Контроль»

«Офис Контроль» — это профессиональная корпоративная панель мониторинга систем безопасности, ИИ-видеонаблюдения за сотрудниками, автоматизации коридоров, архивов и датчиков ЧС (пожар, утечки воды, газов).

## Основные разделы веб-версии
1. **Главная панель (Dashboard):** Сводные метрики присутствия, активности, круговые диаграммы уязвимостей, переключатель режимов офиса (Рабочий день, После работы, Выходной) и кнопка экстренного вызова ЧОП.
2. **Мультиэкран камер:** Одновременный стриминг всех онлайн-каналов в единый экранный квадрант с цифровым зумом, рамками нейросети YOLO и полным экраном.
3. **Реестр сотрудников:** Фото-биометрия лиц, статистика активности, графики прихода/ухода, редактирование данных и экспорт в Excel.
4. **Интерактивный план зон:** Векторная SVG-схема помещений, меняющая цвет в зависимости от уровня датчиков движения или задымления.
5. **Журнал событий:** Пагинируемая таблица (10 строк) с детекциями ИИ, скриншотами-доказательствами нарушений и эскалацией происшествий ЧС.
6. **Правила ИИ:** Простой и гибкий конструктор правил «ЕСЛИ-ТО» под различные рабочие смены.
7. **Аналитика (Admin):** Защищенная зона со сводками дисциплины сотрудников, экспортом кадровых отчетов и графиками Recharts.
8. **Параметры и пользователи:** Настройки локального IP-адреса хоста сервера, резервного копирования и добавление учетных записей операторов.

## Архитектурные особенности веб-приложения

Приложение разработано на современном техническом стеке:
- **React + TS** — модульные хуки и типизация структур (`src/types/index.ts`).
- **Material UI (MUI v5)** — брендированная тема, компоненты и адаптивные карточки.
- **Zustand** — производительный менеджер глобального состояния без бойлерплейта Redux.
- **Recharts** — интерактивные графики распределения событий и плотности посещаемости.

## Как запустить приложение локально

1. Убедитесь, что у вас установлен **Node.js LTS** (версии 18 или выше).
2. Установите зависимости проекта:
   ```bash
   npm install
   ```
3. Запустите сервер разработки Vite:
   ```bash
   npm run dev
   ```
4. Откройте приложение в браузере по адресу:
   ```
   http://localhost:3000
   ```

## Инструкция по переходу от Mock-данных к реальному API

В текущей версии все методы чтения и записи реализованы в виде реактивных экшенов в Zustand-хранилищах и используют статичную базу моков (`src/data/mockData.ts`) с имитацией сетевой задержки запросов `800ms`.

Для миграции на реальное серверное API выполните следующие шаги:

### 1. Подключение библиотеки Axios и конфигурация клиента
Создайте файл `/src/lib/api.ts` для централизованной отправки HTTP-запросов к вашему бэкенд-серверу:

```typescript
import axios from 'axios';

// Извлекаем адрес сервера из настроек приложения
const getApiUrl = () => {
  const server = localStorage.getItem('office_server_address') || '192.168.1.100:8080';
  return `http://${server}/api/v1`;
};

export const api = axios.create({
  timeout: 10000,
  headers: {
    'Content-Type': 'application/json',
  }
});

// Автоматически подставляем актуальный базовый URL при каждом запросе
api.interceptors.request.use((config) => {
  config.baseURL = getApiUrl();
  const token = localStorage.getItem('auth_token');
  if (token) {
    config.headers.Authorization = `Bearer ${token}`;
  }
  return config;
});
```

### 2. Замена мок-экшенов в Zustand на асинхронные HTTP-запросы
Пример обновления хранилища сотрудников `/src/store/officeStore.ts`:

**Было (Имитация моков):**
```typescript
addEmployee: (emp) => set((state) => ({
  employees: [...state.employees, { ...emp, id: String(state.employees.length + 1) }]
})),
```

**Стало (Реальное API):**
```typescript
import { api } from '../lib/api';

// Внутри actions в officeStore:
fetchEmployees: async () => {
  try {
    const response = await api.get('/employees');
    set({ employees: response.data });
  } catch (error) {
    console.error('Ошибка получения сотрудников с сервера:', error);
  }
},

addEmployee: async (emp) => {
  try {
    const response = await api.post('/employees', emp);
    set((state) => ({
      employees: [...state.employees, response.data]
    }));
  } catch (error) {
    console.error('Не удалось добавить сотрудника в БД:', error);
    throw error;
  }
},
```

### 3. Интеграция REST API эндпоинтов камер и журналов с датчиков
Бэкенд-сервер должен предоставлять следующие ключевые эндпоинты:
- `POST /api/v1/auth/login` — Авторизация оператора, выдача JWT токена.
- `GET /api/v1/cameras` — Получение списка потоков ИИ, статусов задымлений и YOLO счетчиков.
- `GET /api/v1/events` — История нарушений безопасности с пагинацией и сортировкой за период.
- `POST /api/v1/events/:id/acknowledge` — Подтверждение происшествия оператором.
- `POST /api/v1/emergency/trigger` — Активация сирен ГО и ЧС со звуковым динамиком.

Подобный переход гарантирует высокую скорость отклика и полную совместимость с реальными контроллерами СКУД и датчиками на объекте.
